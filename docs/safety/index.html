Informed repair

Scan first. Approve changes deliberately.

The full scan reads system state. Repair actions are separated, explained, and started only after approval.

Important: Back up important work and create a Windows restore point before high-impact repairs.

What a scan changes

A general scan does not change Windows settings. It reads services, packages, registry values, event evidence, network state, storage, drivers, and related system information. Navigation is locked during the scan so the operation stays consistent, and the scan can be cancelled.

Repair risk levels

LevelExamplesWhat to expect
Lower impactDNS cache clear, service start, safe cache cleanupUsually reversible or limited in scope.
Higher impactApp reset, package re-registration, Gaming Services reinstall, DISM/SFCMay sign you out, alter package state, take longer, or require restart.
Manual onlyAccount, subscription, policy, remote outage, reinstalling a gameThe tool explains the next action but does not perform it.

Verification after repair

Relevant checks run again when possible. A repair is not labeled successful merely because its command exited. Results can be successful, partial, pending, or failed.

Restart behavior

The tool distinguishes required and recommended restarts. It does not restart Windows without permission. Some Store, package, service, or system-file changes cannot be fully verified until after reboot.

Undo limitations

The latest repair session is kept in Repair History. Settings captured before repair can be restored where supported. Package resets, Store installations, cache removal, Windows repairs, and changes completed by external components may be only partially reversible or irreversible.

Practical rule: Start with low-impact repairs, verify the result, and escalate only when evidence still points to the same layer.
